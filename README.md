# RFQ 智能报价平台 · 可点击演示

汽车零部件供应商的询价报价协同平台演示：一份主机厂询价（RFQ）从收邮件、读规范、技术评审、成本核算，一直走到审批、提交和 ERP 导入，每一步谁做、AI 帮什么、人在哪里把关，都可以点着走一遍。

**在线体验：** https://zeroonehub.github.io/rfq-quote-platform/

> 这是演示版。客户、零件、价格和指标都是示例数据；页面里的 AI 结果是预先写好的示例，不调用真实模型。

---

## 它要解决什么问题

供应商收到主机厂询价后，要在截止日期前读完几十到上百页的中英文技术规范，完成技术评审、成本核算和多级审批。靠 Excel 和邮件接力时，常见的问题有四个：

| 问题 | 表现 |
|---|---|
| 要求读不全 | 关键要求藏在表格、跨页段落和“见附录 C”这类引用里，逐条摘录又慢又容易漏 |
| 进度看不见 | 一份报价走到哪一步、卡在谁那里，只能挨个问 |
| 同一零件算出不同价 | “损耗率”一词两用、毛重净重混用，不同人算出来不一样，也没法复算 |
| 经验在少数人脑子里 | 相似项目怎么报、哪些参数要警惕，靠几位资深成本工程师 |

## 怎么体验（约 10 分钟）

打开页面后，顶部有一条 **体验路线**，按顺序点“去做”就能走完一份询价：

1. 收到一封新询价：在报价单列表点“模拟收到一封新询价”
2. 确认登记：核对 AI 抽取的字段，截止日期和客户必须人确认
3. 确认分级：看 AI 给出的类型和优先级建议
4. 确认要求清单：左边原文、右边清单，处理一条标为“可疑”的要求
5. 处理关键要求“没找到”：补位置、标不适用，或者加入澄清
6. 确认澄清和偏差清单：采纳、修改或删除 AI 起草的条目
7. 看图纸字段：改正一个标黄的低置信度字段
8. 技术评审：给出可行性结论
9. 成本核算：看相似项目、改参数、填人工判断节点、回价更新
10. 审批、提交、登记结果：生成审批流、客户模板和 ERP 导入文件
11. 看看板：运营页、统计页、效果页

## 关键设计

**1. 形态是“固定工作流 + 规则引擎 + 业务本体”，不是 Agent**

报价的流程是固定的，价格必须能复算，报错了收不回来。所以流程用工作流，算钱用规则引擎；大模型只放在流程里 8 个固定节点上：

| AI 节点 | 做什么 | 没把握时 | 谁确认 |
|---|---|---|---|
| 邮件分类 | 新询价 / 补充文件 / 其他 | 归到“未识别邮件” | 商务每天看一次 |
| 信息抽取 | 客户、项目、截止日期等字段 | 字段标黄 | 截止日期和客户必须人确认 |
| 询价分级 | 类型、优先级和理由 | 标“建议人工判断” | 商务主管 |
| 要求清单 | 从规范里逐条摘要求 | 标“可疑” | 逐条或整组确认 |
| 关键要求检查 | 对照检查表找每一项 | 一律标“没找到” | 每个“没找到”逐项处理 |
| 澄清和偏差起草 | 起草要问客户的问题 | 不提 | 工程师和商务 |
| 外文对照 | 外文规范的中文对照 | — | 只供理解 |
| 图纸字段 | 从图纸读取字段和位置 | 字段标黄 | 字段确认 |

**2. AI 不碰价格**

成本和价格由规则引擎按审定过的公式计算，同样的输入一定得到同样的结果。关键参数超出范围自动触发审批；人工覆盖计算结果要写理由，超过 5% 要成本规则负责人确认。

**3. 业务本体：先把口径定下来，再交给系统**

把产品、BOM、零件、材料、工艺、节拍、费率、报价单之间的关系和字段定义清楚。可计算的写成公式，可约束的写成规则，依赖经验的写成**人工判断节点**。例如“损耗率”一词两用会造成重复计算，就拆成“材料利用率”和“制造废品率”两个字段。

**4. 每条 AI 结果都能点回原文**

系统自动把“原文”字段回查到文件，查不到就标“可疑”，必须人工处理；所有 AI 结果都标“AI 生成”，确认后记录确认人和时间。

**5. 分三期，每期都有上线标准**

| 期 | 目标 | 内容 |
|---|---|---|
| 一期 | 读得全、跟得住 | RFQ 登记、询价分级、规范和图纸解析、报价单管理；不碰定价 |
| 二期 | 算得一致、找得到 | 成本核算引擎、成本库、相似项目检索；和原来的 Excel 双轨运行，差异逐条解释后再切换 |
| 三期 | 全链路打通、看得清 | 客户模板、分级审批、ERP 推送、报价看板 |

## 方案架构（简述）

```
询价邮箱 / 文件包
      │
      ▼
 工作流引擎 ── 报价单状态机（登记 → 分级 → 解析 → 评审 → 核算 → 审批 → 提交 → 定点）
      │
      ├── AI 节点：文档解析 → 要求抽取 → 关键要求检查 → 澄清起草 → 图纸字段
      │      （内网部署的开源模型；结果回查原文；没把握交给人）
      │
      ├── 规则引擎：业务本体里的公式、规则、人工判断节点（AI 不参与）
      │
      └── 相似项目检索：文字 + 图纸向量检索，加本体字段过滤
      │
      ▼
 审批 → 客户模板 → ERP 导入文件 → 看板
```

- 全部内网部署，内部数据不出厂，只能用能本地部署的开源模型；
- 模型选型：先把各家主流开源模型列全，按显存、许可证、中英文能力初筛，再用历史询价做金标准分两轮评测，看要求召回率、精确率、原文可溯源率和图纸字段准确率。
